# Сказка-диалог (Interactive Story) — дизайн фичи

**Дата:** 2026-05-28
**Статус:** утверждено пользователем, готово к плану реализации
**Связанные:** [озвучка голосом родителя](../../../.claude/projects/-Users-igor-Projects-fairy-tale-app/memory/project_voice_feature.md) (отдельная фича)

---

## 1. Цель и ценность

Второй режим генерации сказки, в котором текст содержит структурированные **пропуски с подсказками**. Родитель читает вслух; в местах пропуска ребёнок завершает фразу своим словом; родитель тапает плашку — она "схлопывается" как прочитанная. Картинки не генерируются.

**Ценность:**
- Удержание внимания — ребёнок ждёт "свою реплику"
- Развитие речи, фантазии, словарного запаса
- Эмоциональная связь родителя и ребёнка через совместное творчество
- Уникальность каждого прочтения

**Не цель:** заменить классический режим, добавить ASR, ветвить сюжет по ответу.

---

## 2. Принятые продуктовые решения

| Развилка | Решение | Обоснование |
|---|---|---|
| Механика "пропуска" | **Пауза** — родитель читает, ребёнок говорит. Никакого ввода в приложение. | MVP за один заход, без ASR/инпутов, не ломает уютное чтение перед сном |
| Влияет ли ответ на сюжет | **Нет** — текст фиксирован при генерации | Простая архитектура, нет live-генерации |
| Плотность пропусков | **Адаптивно по возрасту** (3-4: 2-3/сцена, 5-6: 4-5, 7-9: 5-7, 10+: 4-6) | Возраст уже есть в форме, промпт сам решает |
| Точка входа | **Вторая кнопка** рядом с "Создать сказку" | Решение в момент действия, нулевая когнитивная нагрузка до этого |
| Визуал пропуска | **Цветная плашка с подсказкой** внутри: `[ какого цвета? ]` | Разгружает родителя наводящим вопросом, видно при беглом чтении |
| После ответа ребёнка | **Тап → плашка "схлопывается"** (полупрозрачная, зачёркнутая) | Визуальный прогресс, не отвлекает от контакта с ребёнком |
| Картинки | **Не генерируем** в этом режиме | По ТЗ + ускоряет генерацию |
| Платформы | **Web + мобильный браузер + Telegram Mini App** | Все три уже поддерживает приложение |

## 3. Модель данных

Расширяем существующий `Story` без поломки старого формата.

```ts
interface Story {
  title: string
  scenes: Scene[]
  mode?: 'classic' | 'interactive'   // default = 'classic'
  // discussion, anchor, storySeed — без изменений
}

interface Scene {
  text?: string                       // используется в classic (как сейчас)
  segments?: Segment[]                // используется в interactive
  imagePrompt: string                 // остаётся; в interactive игнорируется
}

type Segment =
  | { type: 'text';  value: string }
  | { type: 'blank'; hint: string; id: string }
```

**Обратная совместимость:**
- Старые сохранённые сказки (localStorage + Supabase) не имеют `mode`/`segments` → рендерятся как classic
- В classic-сцене может быть только `text`, в interactive — только `segments`. Валидация на рендере.
- `id` пропуска — стабильный (`s{sceneIndex}-b{blankIndex}`), нужен для трекинга "прочитано" в React-стейте.

## 4. Бэкенд — `/api/generate`

**Изменения в `app/api/generate/route.ts`:**

1. Принимает дополнительное поле `mode: 'classic' | 'interactive'` (default `'classic'`).
2. При `mode === 'interactive'`:
   - Используется альтернативный промпт-блок поверх существующего `buildRuPrompt` (и его локализованных версий).
   - Промпт требует возвращать JSON со схемой `scenes[].segments` вместо `scenes[].text`.
   - Адаптивная плотность пропусков задаётся в промпте на основании возраста:
     - **3-4 года:** 2-3 пропуска на сцену, подсказки в 1-2 слова ("какого цвета?", "кто это?", "что сказал?")
     - **5-6 лет:** 4-5 пропусков, средние ("что почувствовал?", "как поступил?", "куда побежал?")
     - **7-9 лет:** 5-7 пропусков, открытые ("почему он так решил?", "что было дальше?")
     - **10+ лет:** 4-6 пропусков с богатыми открытыми вопросами на сюжетные развилки
   - Подсказки — на локали запроса (паттерн locale-aware промптов уже есть в проекте).
   - `imagePrompt` всё равно требуется в схеме (для обратной совместимости типа), но может быть пустой строкой.
3. **Пропускаем `prefetchImages`** при `mode === 'interactive'` — экономим время и Pollinations rate-limit.
4. Fallback по моделям (`gemini-2.5-flash` → `gemini-2.0-flash` → `gemini-flash-latest`) — без изменений.
5. Лимиты, `canGenerate()`, биллинг, аналитика PostHog — те же, что и для classic. В события добавить поле `mode`.

**Промпт interactive-режима (черновик ключевых требований):**
- Полноценная сказка, не "набор пропусков" — основной текст должен литься, пропуски в естественных местах
- Никаких `___` или плейсхолдеров внутри `value` текстовых сегментов
- Подсказка `hint` — короткая, конкретная, наводит на ответ, не даёт его
- Подсказки не дублируются подряд (не "цвет?", "цвет?", "цвет?")
- Сегменты в `segments[]` идут в порядке чтения; первый и последний — `text`, не `blank`
- Длина суммарного текста — та же, что в classic для данного возраста

## 5. UI — точка входа в форме

Файл: `app/[locale]/page.tsx`

**Изменения:**
- Под формой создания — две кнопки рядом:

  ```
  [ ✨ Создать сказку ]    [ 💬 Сказка-диалог ]
        primary                  secondary
  ```

- Обе кнопки используют одни и те же поля формы, лимиты (`canGenerate()`), модалки (auth, name).
- Кнопка "Сказка-диалог" вызывает тот же handler генерации, передавая `mode: 'interactive'`.
- Состояния `idle` / `loading` / `done` — общие.
- На мобильном — кнопки в столбик, full-width (responsive Tailwind).

**Визуальная иерархия:**
- Primary "Создать сказку" — основной CTA-цвет проекта.
- Secondary "Сказка-диалог" — outline / muted фон с тем же контуром, иконка `💬` или SVG-чат.
- В сёгменте десктопа — кнопки одинаковой высоты, ширина по содержимому.

## 6. UI — отображение сказки

Новый компонент `components/InteractiveScene.tsx`:
- Принимает `Scene` (с `segments`) и индекс сцены
- Рендерит сегменты inline в одном текстовом потоке
- `text` → обычный `<span>` (наследует typography сцены)
- `blank` → `<button>` плашка

**Стили плашки (Tailwind):**

| Состояние | Внешний вид |
|---|---|
| Не прочитано | `inline-flex` с фоном `bg-amber-100/peach`, скруглённая `rounded-full`, паддинг `px-2.5 py-0.5`, `text-amber-900`, `font-medium`, шрифт чуть меньше тела (`text-[0.95em]`). Внутри: `[ hint ]` |
| Прочитано | `opacity-40`, `line-through`, фон тот же но `bg-stone-100`. Hint остаётся видим. |
| Hover (desktop) | `hover:brightness-95` |
| Active (mobile) | `active:scale-95 transition-transform` |

**Состояние "прочитано":**
- Хранится в `useState<Set<string>>(new Set())` внутри `InteractiveScene` (или родителя)
- Не персистится — каждое открытие сказки = чистый старт
- Тап тоггл (можно "вернуть" пропуск)
- Ключ — `id` сегмента (`s{sceneIndex}-b{blankIndex}`)

**Картинки:**
- В interactive-сказке `<StoryImage>` не рендерится
- Структура сцены без `<StoryImage>` — текст занимает всю ширину

## 7. Мобильность и Telegram Mini App

**Мобильный браузер:**
- Кнопки формы — в столбик, full-width, как остальная форма
- Плашка — `min-h-[44px]` неприменимо к inline-элементу; вместо этого `py-1` + увеличенный `line-height` родителя для inline tap target ≥ 32px по высоте; ширина — естественная по контенту, минимум `min-w-[3rem]`
- Плашка `white-space: nowrap` — не разрывается между строк, но переходит на новую строку целиком
- Тапы — обычный `onClick`, `active:scale-95` для тактильной обратной связи
- Шрифт сцены — крупный (как уже в проекте)

**Telegram Mini App:**
- Используется существующий `window.Telegram.WebApp` integration
- Никаких modal/alert при тапе на плашку (только смена inline-стиля)
- Главная кнопка Telegram (`MainButton`) — без изменений
- Тема: использовать существующие токены/CSS-переменные проекта; не хардкодить цвета, чтобы плашка адаптировалась к тёмной/светлой теме Telegram, если она поддерживается в проекте

**Чего НЕ делаем:**
- Свайпы, long-press, drag-and-drop — обычного тапа достаточно
- Отдельный mobile layout — Tailwind responsive покрывает

## 8. Сохранённые сказки

- `SavedStory` сохраняется в localStorage и (для авторизованных) в Supabase — структура расширяется естественно через optional поля
- В библиотеке (карточка сказки) — бейдж `💬 диалог` рядом с заголовком для interactive
- Открытие сохранённой → рендерится через `<InteractiveScene>`, состояние "прочитано" сбрасывается
- Старые сказки без `mode` → рендерятся как classic (текст + картинки)

## 10. Печать (`@media print`)

В `app/globals.css`:
- Плашка → подчёркнутая линия шириной `~3-4em` (`border-bottom`, `min-width`)
- Hint → курсивом мелким шрифтом под линией (`display: block; font-style: italic; font-size: 0.75em;`)
- Состояние "прочитано" игнорируется (печатается чистая версия)
- Фон плашки сбрасывается (`background: transparent`)

В существующие события генерации добавить поле `mode: 'classic' | 'interactive'`. Новых событий не вводим в MVP.

## 12. Что НЕ делаем (явный YAGNI)

- ❌ Голосовой ввод (ASR / Web Speech / Whisper)
- ❌ Сохранение ответов ребёнка ("наша версия сказки")
- ❌ Ветвление сюжета по ответу
- ❌ Озвучка — пересекается с уже запланированной voice-фичей
- ❌ Аналитика "какие подсказки чаще схлопываются"
- ❌ Долгий тап / свайпы / жесты
- ❌ Отдельная страница / роут — фича внутри существующей `[locale]/page.tsx`
